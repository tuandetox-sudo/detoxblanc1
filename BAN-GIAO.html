  • Layout guards CSS — chống vỡ bố cục khi admin nhập dữ liệu thật ~150 dòng CSS: table truncate + ellipsis · modal overflow-y:auto · word-break cho mono/code/email · sticky modal-foot · mobile 1-col · min-width tables 980/1100px · title= tooltip cho cell bị cắt
  • Inventory atomic + product-level stock — fix race condition oversell + SP không có variant Postgres UPDATE … WHERE (stock-reserved) ≥ qty đảm bảo atomic. Thêm field Product.stock. Fix commitStock/receiveStock/reserveStock/releaseStock. Aggregator + alerts + adjust/set/count routes hỗ trợ cả 2 level.
  • RMA / Cancel-after-ship / Tracking — endpoint mới + 2 model schema State machine 5 trạng thái: requested → inspecting → approved → refunded (hoặc rejected). Refund điểm thưởng tỉ lệ với phần trả. Restock optional. Tracking carrier + URL. Order.cancelReason, returnedAt, OrderReturn, OrderReturnItem.
  • 17 bridge functions FE↔BE trong assets/admin-api.js Orders 7 fn (adminCreate, setTracking, cancelAfterShip, createReturn, updateReturn, listReturns, validateVoucher) · Customers 11 fn (recomputeLoyalty, communications, consent, addresses CRUD, import, merge) · Inventory 5 fn (receive, receiveBulk, count, alerts, movements).
  • RBAC FE — file mới assets/admin-rbac.js + thuộc tính data-perm Tự gọi /auth/me, build permissions Set, xoá DOM (chống bypass F12), MutationObserver bắt row mới render. 22 button đã gắn perm trên 12 trang admin. BE vẫn là nguồn đúng (mọi route có requirePermission).
  • Rich staging seed — api/prisma/seed-staging.ts 50 KH × 70 đơn × 18 SP × 6 voucher · refuse khi DB trông giống prod (regex check DATABASE_URL). Mọi segment KH đầy đủ: new_cus / active / vip / at_risk / churn / blacklist. Trạng thái đơn đa dạng để test UI.

Rewrite được cấu hình ở 4 layer:

  • Apache (cPanel/Plesk Linux): file .htaccess với 19 RewriteRule
  • IIS (Plesk Windows/Azure): file web.config với 19 rule
  • Nginx (VPS): block location ^~ /admin/ với rewrite directives
  • Firebase: firebase.json rewrites array (cộng cleanUrls: true)

FE auto-detect API base

File assets/env-detect.js chạy trước mọi script khác:

HostnameModeAPI base
localhost / 127.x.x.xlocal/v1
*.web.app / *.firebaseapp.com / *.run.applocal (demo, FE-only)/v1
detoxblanc.comremotehttps://api.detoxblanc.com/v1
Khác (default)remote/v1 (qua reverse proxy)

Override bằng <meta name="dtx-api-base" content="..."> hoặc localStorage.setItem('DTX_API_BASE_OVERRIDE', '...').

Lệnh chạy 1 dòng (Path A — production)

# Sau khi đã setup project + secrets (xem DEPLOY-GOOGLE.md mục 0)
PROJECT_ID=detoxblanc-prod ./scripts/deploy-google.sh

Script sẽ:

  1. Build & push API image, deploy detoxblanc-api (internal, no public access)
  2. Build & push Web image, deploy detoxblanc-web (public)
  3. Cấp quyền Web invoke API (IAM run.invoker)
  4. Set API_UPSTREAM env trên Web → Web nginx tự reverse-proxy

Resource cần chuẩn bị (xem DEPLOY-GOOGLE.md chi tiết)

  • Cloud SQL Postgres 16 (db-f1-micro tiết kiệm cho start) — detoxblanc-db
  • Memorystore Redis (BASIC 1GB) — detoxblanc-redis
  • Secret Manager: 5 secrets (DATABASE_URL, REDIS_URL, JWT_SECRET, JWT_REFRESH_SECRET, COOKIE_SECRET)
  • Service account: detoxblanc-api với role cloudsql.client + secretmanager.secretAccessor
  • Artifact Registry: repo detoxblanc ở region asia-southeast1

Custom domain

gcloud run domain-mappings create \
  --service=detoxblanc-web \
  --domain=detoxblanc.com \
  --region=asia-southeast1

9 Go-live · 4 phase Production rollout

D-7→D-3

Chuẩn bị

Chạy pnpm prisma migrate dev --name oms_v1_returns_tracking, review SQL, setup staging env vars (DATABASE_URL, REDIS_URL, 3 JWT secrets), install Sentry + alert rules, check toàn bộ secrets ở Secret Manager. Backup DB hiện tại.

D-3→D-0

UAT

Deploy staging, chạy prisma:seed:staging (50 KH × 70 đơn × 18 SP × 6 voucher), ban vận hành test 7 kịch bản KB1-KB7 (orders flow / RMA / cancel-after-ship / inventory PO / count / customer drawer / voucher). Fix bug nếu có. Đo response time + error rate.

W1→W2

Pilot

Rollout 1 chi nhánh hoặc 1 nhóm KOL. Monitor (Sentry + Cloud Logging + alert rules). So sánh metric với baseline cũ: GMV, AOV, fill-rate, response time, error rate. Daily standup 5 phút trong tuần đầu.

W3+

Full go-live

Rollout toàn hệ thống. Suggested date: 2026-05-15. Truyền thông nội bộ + đào tạo ops 1 buổi 2h. Standby on-call 24/7 trong tuần đầu.

7 kịch bản UAT (KB1-KB7)

  1. Orders flow: tạo đơn từ POS → confirm → packing → shipping (gắn tracking) → delivered
  2. RMA partial: KH trả 2/5 sản phẩm sau delivered → approve → restock + refund pro-rata
  3. Cancel-after-ship: đơn shipping bị từ chối → cancel-after-ship với reason → tự sinh case RMA approved
  4. Inventory PO: nhập 50 SKU từ PO với cost khác → moving-average tính đúng → audit movement
  5. Physical count: kiểm kê lệch ±10 → tạo movement count → audit có hash
  6. Customer drawer: open KH VIP → 6 tab (info, addresses, orders, communication, loyalty, consent) → CRUD address + log communication
  7. Voucher: tạo SUMMER25 25%, FREESHIP 100%, GIFT100K 100k → validate trong checkout → apply đúng + tăng usedCount

10 Rollback + Monitoring Safety net

Rollback 24h an toàn

  • FE: đặt env DTX_API_MODE=local → quay về localStorage seed (mất tính năng API nhưng không downtime)
  • API: rollback Cloud Run revision: gcloud run services update-traffic detoxblanc-api --to-revisions=detoxblanc-api-NNNN-xxx=100
  • DB: nếu schema migration phá vỡ → prisma migrate resolve --rolled-back + pg_restore từ backup
  • Tất cả deploy đều giữ revision cũ → 1 lệnh rollback < 30s

Monitoring

  • Sentry cho FE + BE error tracking
  • Cloud Logging filter severity≥ERROR + auto alert qua Slack/Email
  • Cloud Monitoring uptime check mỗi 60s
  • Alert rules: response time p95 > 1s · error rate > 1% · DB connection > 80% · memory > 90%
  • Dashboard tổng hợp ở Cloud Console

Real-time logs lệnh thường dùng

gcloud run services logs tail detoxblanc-api --region=asia-southeast1
gcloud run services logs tail detoxblanc-web --region=asia-southeast1
gcloud run services logs read detoxblanc-api --region=asia-southeast1 \
  --filter="severity>=ERROR" --limit=50
