7/7 nhóm P0 đã xử lý

  • Layout guards CSS — chống vỡ bố cục khi admin nhập tên SP/địa chỉ/email dài. table truncate + ellipsis · modal overflow-y · word-break mono · sticky modal-foot · mobile 1-col · min-width tables 980/1100.
  • Inventory atomic + product-level — fix oversell race condition + SP không có variant. UPDATE … WHERE (stock-reserved)>=qty trên Postgres → row-lock chống đặt cùng lúc; Product.stock field mới.
  • RMA / Cancel-after-ship / Tracking — endpoint mới + 2 model schema. State machine 5 trạng thái (requested→inspecting→approved→refunded), refund điểm thưởng tỉ lệ, restock optional.
  • 17 bridge functions FE↔BE — assets/admin-api.js. Orders 7 fn · Customers 11 fn · Inventory 5 fn — đầy đủ create/return/tracking/voucher/loyalty/consent/address/import/merge/receive/count/alerts.
  • RBAC FE — assets/admin-rbac.js + thuộc tính data-perm. Tự gọi /auth/me, build permissions Set, xoá DOM (chống F12), MutationObserver bắt row mới render.
  • Rich staging seed — api/prisma/seed-staging.ts. 50 KH × 70 đơn × 18 SP × 6 voucher · refuse khi DB trông giống prod.
  • PRODUCTION-CHECKLIST.md — go-live 4 phase + rollback + monitoring + handover. D-7 chuẩn bị · D-3→D-0 UAT (KB1–KB7) · W1–W2 pilot · W3+ full · 24h fallback.

Quy trình go-live (4 giai đoạn)

  • D-7 → D-3 — Chuẩn bị: chạy pnpm prisma migrate dev --name oms_v1_returns_tracking, review SQL, setup staging env vars, install hooks.
  • D-3 → D-0 — UAT: deploy staging, chạy prisma:seed:staging, ban vận hành test 7 kịch bản KB1–KB7 (xem checklist mục 3.2).
  • W1 → W2 — Pilot: 1 chi nhánh hoặc 1 nhóm KOL, monitor (Sentry + alert rules), so sánh metric.
  • W3+ — Full go-live: rollout toàn hệ thống. Suggested date: 2026-05-15.

Rollback an toàn 24h: đặt DTX_API_MODE=local để FE quay về localStorage; prisma migrate resolve --rolled-back nếu cần.

Lưu ý cho người thật trước khi nhận bàn giao

  • Nhập SP có dấu / ký tự đặc biệt: layout guards đã set word-break và title= tooltip — hover row sẽ xem được nội dung đầy đủ kể cả khi cell bị truncate.
  • Modal có nội dung dài: drawer/modal có overflow-y:auto + position:sticky ở footer → nút Lưu/Huỷ luôn nhìn thấy.
  • Mobile (≤720px): form 2 cột tự sập về 1 cột, table có scroll ngang riêng → không vỡ giao diện.
  • Quyền nhân viên: button bị xoá khỏi DOM nếu thiếu data-perm — không phải chỉ ẩn. Mã JS handlers vẫn nên gọi DTX_ADMIN_PERMS.requireOrToast(...) trước khi submit.
  • BE là nguồn đúng: tất cả route đều có requirePermission(...). Nếu KH/admin bypass FE, BE vẫn từ chối với 403.
